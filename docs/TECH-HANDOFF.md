# خطة التسليم التقني — استوديو حكايات العائلة
> وثيقة يستلمها فريق التطوير. النسخة ١.٠ — سبتمبر ٢٠٢٦.
> المرجع: خطة المعمارية (PDF) + محضر الاجتماع الاستراتيجي + بروتوتايب `prototype/index.html`.

---

## 0) القرارات المعمارية (ADR) — غير قابلة للتفاوض
| # | القرار | السبب |
|---|--------|-------|
| 1 | **ويب أولاً (PWA موبايل-فيرست)** | أسرع طريق لإثبات الدفع؛ لينك يتشارك (جوهر الهدية)؛ كود واحد |
| 2 | **Modular Monolith** (مش microservices) | فريق صغير، سرعة، تجنّب تعقيد مبكر |
| 3 | **كل توليد ثقيل في Job Queue** | لا يمر عبر طلب الـAPI أبدًا؛ الـAPI يرجع `jobId` فورًا |
| 4 | **الملفات ترفع/تنزل مباشرة من التخزين** عبر signed URLs | لا تمر ملفات الصوت/الفيديو الكبيرة عبر السيرفر |
| 5 | **النص = مصدر الحقيقة، الصوت = الأداء، بموافقة صريحة** | صوت الأب البالغ فقط؛ ممنوع استنساخ صوت طفل |
| 6 | **الخصوصية افتراضية + حذف كامل + سجل تدقيق** | التزام PDPL السعودي + COPPA |
| 7 | **الهوية البصرية الثابتة للشخصية = الميزة الحاسمة** | أصعب جزء تقنيًا وأهم عامل تمايز |

## 1) الستاك التقني
**الواجهة (Frontend)**
- Next.js 15 (App Router) + TypeScript + Tailwind CSS
- PWA (installable, offline shell), RTL كامل، خط IBM Plex Sans Arabic
- توكنز التصميم جاهزة في `family_tales_studio/DESIGN.md` والبروتوتايب
- تسجيل الصوت: `MediaRecorder API` (معالجة فرق صيغ iOS سيرفر-سايد)

**الباك إند (Backend) — Java**
- **Java 21 + Spring Boot 3.x** (modular monolith، وحدات بحدود واضحة داخل نفس التطبيق)
- Spring Web (REST) + Spring Security (JWT) + Spring Data JPA
- **PostgreSQL** قاعدة البيانات الرئيسية
- **RabbitMQ** (أو Redis) لطابور المهام + عمّال (workers) كعمليات منفصلة
- **S3-compatible storage** (MinIO محليًا / أي S3 إنتاجًا) + signed URLs
- Flyway لهجرات الـDB

**خدمات الذكاء (تُستدعى من العمّال فقط، خلف واجهات مجرّدة)**
- STT (تفريغ): **Azure Speech** (أفضل للعربية واللهجات الخليجية) أو Whisper
- توليد الصور بهوية ثابتة: SDXL + IP-Adapter/LoRA عبر Replicate/fal.ai
- TTS بصوت الأب: ElevenLabs (مؤجّل — انظر مرحلة الجودة)
- تجميع الفيديو: **FFmpeg** (Ken Burns على الصور + سرد + موسيقى)

> **مبدأ**: كل مزوّد ذكاء خلف `interface` (SttProvider, ImageProvider, TtsProvider). نبدّل المزوّد دون لمس منطق العمل.

## 2) وحدات النظام (Modules داخل المونوليث)
```
com.familytales
├── auth            المصادقة، الحسابات، الجلسات (JWT)
├── story           الحكاية، المسودات، المشاهد، اعتماد النص
├── voice           التسجيل، التفريغ (STT)، موافقة الصوت
├── character       بطاقة الشخصية + الهوية البصرية الثابتة  ← الميزة الحاسمة
├── render          منسّق التوليد (Orchestrator): صور → صوت → فيديو
├── media           التخزين، signed URLs، دورة حياة الأصول
├── privacy         الموافقات، سجل التدقيق، الحذف/التصدير
└── jobs            طابور المهام، تتبّع الحالة، إعادة المحاولة
```

## 3) الكيانات (Entities)
`User, Family, FamilyMember, CharacterProfile, Story, StoryRevision, VoiceConsent, VoiceSample, StoryScene, GenerationJob, MediaAsset, DeletionRequest, AuditEvent`

## 4) آلة حالات التوليد (GenerationJob)
```
queued → processing → needs_review → completed
                    ↘ failed
                    ↘ cancelled
```
- الواجهة تعرض مراحل مفهومة: «نرتب الحكاية → نجهّز الأصوات → نصنع المشاهد → المعاينة جاهزة».
- `needs_review` = وقفة إلزامية لاعتماد الأب قبل التصدير.

## 5) عقد الـAPI الأساسي (v1)
```
POST /stories                      إنشاء حكاية
POST /stories/{id}/audio           رفع تسجيل (يرجع signed URL)
POST /stories/{id}/transcribe      تفريغ الصوت → نص (job)
POST /stories/{id}/text            حفظ/تعديل النص
POST /stories/{id}/approve-text    اعتماد النص  ← بوابة
POST /characters                   بطاقة شخصية + هوية بصرية
POST /voice-samples                عيّنة صوت
POST /voice-consents               موافقة صريحة (إلزامية قبل TTS)
POST /stories/{id}/scenes/generate بدء التوليد (job) → jobId
GET  /jobs/{id}                    حالة/تقدّم المهمة
DELETE /media/{id}                 حذف أصل
DELETE /families/{id}              حذف كامل (يشغّل DeletionRequest)
```
> الملفات الكبيرة: `POST /audio` يرجع signed URL، والعميل يرفع **مباشرة** للتخزين.

## 6) خط أنابيب الميديا (Media Pipeline)
1. **الصوت**: العميل يسجّل → يرفع للتخزين → job `transcribe` (STT) → نص قابل للتحرير.
2. **النص**: الأب يعدّل ويعتمد (`approve-text`).
3. **الشخصيات**: بطاقة لكل فرد (اسم/علاقة/عمر/صور مرجعية/نمط) → تُثبّت الهوية عبر كل المشاهد.
4. **الصور**: job لكل مشهد بهوية الشخصية الثابتة (seed/embedding ثابت).
5. **الصوت السردي (MVP)**: **استخدم تسجيل الأب الحقيقي كسرد مباشرة** — لا TTS. (يوفّر تكلفة ومخاطرة).
6. **الفيديو**: FFmpeg يجمع صور المشاهد + السرد + موسيقى هادئة → فيلم قصير (<٩٠ ثانية).
7. **المعاينة**: بعلامة مائية → دفع → نسخة كاملة + أرشيف عائلي خاص.

## 7) الخصوصية والامتثال (إلزامي من اليوم الأول)
- الحساب للأب فقط؛ كل شيء خاص افتراضيًا (الوضع العائلي المقفل).
- `VoiceConsent` صريح قبل أي استخدام للصوت؛ بالغ فقط.
- زر **حذف كامل** يزيل: الصوت + النص + الأصول + المشتقات، مع `AuditEvent` لكل موافقة/حذف.
- **تصدير ZIP** لكامل الأرشيف الشخصي.
- مرجع: PDPL (misa.gov.sa) + COPPA.

## 8) تقسيم فرق العمل (Workstreams المتوازية)
| المسار | المسؤولية | المخرجات |
|--------|-----------|----------|
| **A — الواجهة/المنتج** | تنفيذ الشاشات التسعة من البروتوتايب في Next.js | تدفّق كامل قابل للنقر |
| **B — الباك كور** | auth, story, DB, API, JWT | عقد API v1 يعمل |
| **C — خط الميديا** | jobs, STT, توليد الصور, FFmpeg, تخزين | فيلم يُنتَج من نص+صوت |
| **D — الخصوصية/الامتثال** | موافقات, تدقيق, حذف, تصدير | مطابقة PDPL/COPPA |

> مسار **C (توليد الصور بهوية ثابتة)** هو أعلى مخاطرة — يبدأ كـ spike بحثي في الأسبوع الأول.

## 9) المراحل الزمنية
**المرحلة صفر — أسبوعان** (إثبات الدفع)
- تدفّق: تسجيل/كتابة → نص → اعتماد → بطاقة شخصية واحدة → فيلم شبه-يدوي → معاينة → دفع تجريبي.
- الهدف: **١٠–٢٠ عائلة** تنهي القصة وتقبل المعاينة.

**MVP — ٤ أسابيع**
- حساب الأب، حتى ٣ شخصيات، ٤–٦ مشاهد، معاينة بعلامة مائية، دفع بعد المعاينة، أرشيف خاص.

**الجودة والاقتصاديات — ٤–٦ أسابيع**
- إعادة توليد مشهد واحد، فصحى + لهجة خليجية، قوالب المناسبات، قياس تكلفة الفيلم، TTS بصوت الأب (اختياري)، رضا عن اتساق الشخصية.

## 10) مهام Sprint 0 (نبدأ بها هذا الأسبوع)
1. Repo + مونوريبو (`/web` Next.js، `/api` Spring Boot، `/workers`) + Docker Compose (Postgres, RabbitMQ, MinIO).
2. تنفيذ **الشاشة الرئيسية + شاشة المراجعة** من البروتوتايب في Next.js.
3. Backend: `auth` + `POST /stories` + `POST /stories/{id}/audio` (signed URL).
4. **Spike بحثي**: توليد صورة بهوية شخصية ثابتة عبر مشهدين (Replicate/fal.ai) — قرار المزوّد نهاية الأسبوع.
5. جدول Postgres للكيانات الأساسية + Flyway.

## 11) المخاطر التقنية (وأولها الأخطر)
1. **اتساق هوية الشخصية عبر المشاهد** — الميزة الحاسمة، أصعب تقنيًا. خفّفها بـ spike مبكر ومزوّد قابل للتبديل.
2. **تكلفة التوليد لكل فيلم** — قِسها من أول يوم؛ الفيلم شبه-يدوي في MVP.
3. **صيغ صوت iOS** — عالجها سيرفر-سايد (ffmpeg transcode).
4. **الناس تحب ولا تدفع** — المشكلة عرض قيمة/مناسبة، لا نموذج أفضل. لا نبالغ في البناء قبل الدفع.

### الخلاصة للفريق
